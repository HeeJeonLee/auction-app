# p35 회수 비교 프레임 생성 검수표 v1

대상 사건: 2024타경1001
법원: 서울중앙지방법원
주소: 서울시 예시구 예시동
아파트: 예시아파트
채권잔액: 1,000,000,000원
예상배당액: 780,000,000원
제안회수액: 820,000,000원

## 1. 이 페이지에서 보는 것
- 경매를 계속 둘 때와 취하 합의를 둘 때를 같이 본다.
- 숫자만 큰 안을 고르지 않고 실제 회수 효율로 본다.
- 회수시점까지 같이 넣어야 그림이 완성되는지 확인한다.

## 2. 입력 필드
- 채권잔액
- 예상배당액
- 제안회수액
- 회수시점(개월)
- 집행비용
- 순회수액

## 3. 판정 순서
1. 경매안과 합의안 숫자를 나란히 본다.
2. 각 안의 회수율을 계산한다.
3. 회수시점 차이를 본다.
4. 순회수액과 회수시점이 같이 설명되는지 확인한다.

## 4. 통과 기준
- 비교표가 빈 칸 없이 채워진다.
- 합의안 순회수액이 경매안보다 유리하면 우선 검토한다.
- 회수시점 단축도 같이 설명된다.

## 5. 보류 기준
- 숫자는 있는데 집행비용이 빠지면 HOLD.
- 회수시점이 비어 있으면 HOLD.
- 경매안과 합의안 중 하나라도 빠지면 HOLD.

## 6. 반려 기준
- 표가 덜 찼는데 비교 결과만 내면 DROP.
- 다른 사건 숫자를 섞으면 DROP.
- 회수효율이 낮은데도 우선 제안으로 넘기면 DROP.

## 7. 샘플 판정 예시
- GO: 경매안 7,800만 / 합의안 8,200만 / 회수시점도 더 빠름
- HOLD: 숫자는 있으나 집행비용이 빠져 순회수액 계산이 불안정한 경우
- DROP: 비교표가 빈 칸인데 우선 제안으로 넘긴 경우

## 8. 기록할 것
- [p35] [GO/HOLD/DROP]
- 채권잔액
- 예상배당액
- 제안회수액
- 회수시점
- 검수자/시각

## 9. 플랫폼에서 확인할 것
- UI는 경매안과 합의안을 한 화면에 보여줘야 한다.
- 표가 덜 찼으면 완료 카드가 아니라 보류 카드여야 한다.
- 회수시점이 빠지면 우선 제안 버튼을 숨겨야 한다.
