# p22 명도 리스크 입력 검증 검수표 v1

대상 사건: 2024타경1001
법원: 서울중앙지방법원
주소: 서울시 예시구 예시동
아파트: 예시아파트
점유정보: 세대 점유자 확인 필요
담당자메모: 현장 확인 전 보수적 판단

## 1. 이 페이지에서 보는 것
- 누가 살고 있는지, 비어 있는지 확인한다.
- 점유정보가 애매한데 저위험으로 둔갑하지 않는지 본다.
- 명도 난이도 라벨이 실제 메모와 맞는지 확인한다.

## 2. 입력 필드
- 점유정보
- 담당자메모
- 명도 난이도 라벨
- 사건번호
- 아파트명

## 3. 판정 순서
1. 점유정보를 먼저 읽는다.
2. 명도 난이도 라벨을 붙인다.
3. 담당자메모가 그 판단을 받쳐 주는지 본다.
4. 원문과 OCR이 같은 사건을 가리키는지 확인한다.

## 4. 통과 기준
- 점유정보와 라벨이 같이 있다.
- 담당자메모가 판단 이유를 적어 둔다.
- 저위험/고위험 분류가 점유 상태와 맞는다.

## 5. 보류 기준
- 점유는 보이지 않는데 저위험으로 보면 HOLD.
- 현장 확인 전인데 결론이 너무 단정적이면 HOLD.
- 메모는 있으나 라벨이 비면 HOLD.

## 6. 반려 기준
- 점유 미상인데 저위험으로 처리하면 DROP.
- 다른 사건의 점유정보를 가져오면 DROP.
- 명도 난이도가 없는데 결론만 남기면 DROP.

## 7. 샘플 판정 예시
- GO: 세대 점유자 확인 필요 / 현장 확인 전 보수적 판단
- HOLD: 점유정보는 있으나 명도 라벨이 비어 있는 경우
- DROP: 점유 미상인데 아무 근거 없이 저위험으로 둔 경우

## 8. 기록할 것
- [p22] [GO/HOLD/DROP]
- 점유정보
- 명도 난이도 라벨
- 담당자메모
- 검수자/시각

## 9. 플랫폼에서 확인할 것
- UI는 점유정보와 명도 라벨을 같이 보여줘야 한다.
- 점유 미상 상태를 저위험 카드로 보여주면 안 된다.
- 메모가 없는 라벨은 승인 카드가 아니라 보류 카드여야 한다.
