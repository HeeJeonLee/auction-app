# p10 권리리스크 개수 상한 검수표 v1

대상 사건: 2024타경1001
법원: 서울중앙지방법원
주소: 서울시 예시구 예시동
아파트: 예시아파트
근저당: 1
압류: 1
가압류: 0
가처분: 0
임차권: 0
전세권: 0
가등기: 0

## 1. 이 페이지에서 보는 것
- 권리 플래그 개수가 몇 개인지 센다.
- 3개를 넘으면 정밀검토 큐로 보내야 하는지 본다.
- OCR이 플래그를 빼먹지 않았는지 확인한다.

## 2. 입력 필드
- 근저당
- 압류
- 가압류
- 가처분
- 임차권
- 전세권
- 가등기

## 3. 판정 순서
1. 각 권리 항목을 1개씩 센다.
2. 총 개수를 집계한다.
3. 3초과인지 확인한다.
4. 검토 큐 연동 상태를 확인한다.

## 4. 통과 기준
- 권리 개수가 숫자로 확정된다.
- 3개 이하이면 일반 검수 흐름에 남는다.
- 3초과면 정밀검토 큐로 분기된다.

## 5. 보류 기준
- 항목 수가 서로 다르게 읽히면 HOLD.
- OCR이 권리 이름을 누락하면 HOLD.
- 총 개수는 있으나 항목별 근거가 없으면 HOLD.

## 6. 반려 기준
- 3초과인데 일반 통과로 남기면 DROP.
- 권리 개수를 다른 사건에서 가져왔으면 DROP.
- 근거 없이 개수만 적어두면 DROP.

## 7. 샘플 판정 예시
- GO: 근저당 1 / 압류 1 / 나머지 0, 총 2개
- HOLD: 항목은 보이지만 일부 권리가 OCR에서 잘린 경우
- DROP: 총 4개인데 일반 통과로 남긴 경우

## 8. 기록할 것
- [p10] [GO/HOLD/DROP]
- 권리 개수 합계
- 정밀검토 큐 연동 여부
- OCR 대조 결과
- 검수자/시각

## 9. 플랫폼에서 확인할 것
- UI는 권리 개수와 큐 분기 결과를 같이 보여줘야 한다.
- 3초과인데도 통과 카드가 뜨면 안 된다.
- 권리 이름이 비어 있으면 자동 승인하지 말아야 한다.
