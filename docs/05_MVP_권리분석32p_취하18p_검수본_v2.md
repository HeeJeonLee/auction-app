# MVP 매뉴얼 50P 검수본 v2

범위: 서울/수도권 아파트, 감정가 5억~50억(초과건 별도 트랙)
목표: OCR 결과를 규칙 엔진에 직접 연결해 점수/판정/취하 스크립트를 생성하고, 검수자가 즉시 반려/보완 결정을 내릴 수 있는 실무 문서를 제공한다.
버전: MVP-2026.08-v2

---

## p01. 사건 식별 필수키 정의
- 문서 단계: 권리분석
- 페이지 목표: 해당 규칙을 단독 검수해도 승인/보류/반려를 바로 판단할 수 있도록 근거·예외·후속액션을 명시한다.
- 기존 요약: - 목적: 사건번호/법원명/주소 3키를 필수 식별키로 고정 - 규칙ID: RA-01, RA-02, RA-03 - 입력: 공고문, OCR 텍스트, 사용자 보완 입력 - 절차: 1. 사건번호 정규화(YYYY타경NNNN) 2. 법원명 표준화(지방법원/지원) 3. 주소에서 시군구+동호 분리 - 산출: 사건식별키 검증표 - 예외: 사건번호 미확인 시 즉시 HOLD - 출처: 법원경매정보 사건 기본정보 항목

### 1) 실무 적용 시나리오
- 대표 케이스: 운영 중 발생하는 OCR 누락/오인식 케이스를 전제로, 원문 캡처-추출값-규칙판정 3단 비교로 반려 여부를 판단한다.
- 검수자가 보는 관점: 단일 필드 정답 여부보다, 이 페이지 규칙이 최종 GO/HOLD/DROP에 주는 영향도를 우선 확인한다.
- 판정 원칙: 입력값이 불완전하면 즉시 DROP하지 않고 HOLD로 유도한 뒤 보완 요청을 남긴다. 단, 범위 정책(지역/감정가) 위반은 예외 없이 분리한다.

### 2) 입력/검증/산출 체크리스트
- 입력 필드: 사건번호, 법원명, 주소, 감정가, 부채총액, 주요채권자
- 검증 절차: 원문 캡처 숫자/문구 -> OCR 추출값 -> 규칙 evidence 라인 순서로 3중 대조한다.
- 산출 결과: 규칙점수, 규칙판정, 규칙근거, 취하스크립트가 서로 모순 없이 연결되는지 확인한다.
- 반려 조건: 핵심 필드가 비어 있는데 GO가 나오거나, 근거 없는 결론문이 생성되면 즉시 반려한다.
- 보완 요청 문구: 어떤 필드를 어디서 재수집해야 하는지(예: 사건기본정보 헤더, 배당요구종기, 등기부 권리란)까지 지정한다.

### 3) 오류 패턴 및 예외 처리
- OCR 오인식: 날짜 2026.09.11 -> 2026.09.01, 금액 단위 원/만원 혼동, 사건번호 문자 치환(타경/타걍) 패턴을 우선 의심한다.
- 결합 오류: 다른 물건번호가 한 사건으로 병합되면 주소/동호/물건번호 정합성 검사로 강제 분리한다.
- 정책 충돌: 규칙 점수는 높지만 대상 범위(서울/수도권, 5억~50억) 위반이면 운영 큐에서 분리하고 참고 데이터로만 저장한다.
- 책임 분리: 시스템 자동판정과 최종 실무결정은 분리 기록하고, 최종결정자는 반려/승인 사유를 메모에 남긴다.

### 4) 증빙/로그 포맷(필수)
- evidence 포맷: [PASS/FAIL] RULE_ID (source) field=value
- 검수 메모 포맷: [페이지 p01] [판정 GO/HOLD/DROP] [근거 2줄] [재수집 요청 1줄]
- 저장 원칙: rule_version, failed_rule_ids, recommendations, 취하스크립트 요약을 결과 파일에 함께 보관한다.
- 추적 원칙: 재검수 시 동일 사건의 이전 판정과 달라졌다면 변경 이유를 한 줄로 강제 기록한다.

### 5) 현장 질의 5문항 및 승인 게이트
- 질의1: 이 페이지의 핵심 필드가 원문 캡처에서 실제로 확인되는가?
- 질의2: OCR 추출값과 원문값이 다를 때 어떤 값을 우선 채택했고 근거가 기록됐는가?
- 질의3: 규칙판정이 상위 정책(지역/가격/아파트 범위)과 충돌하지 않는가?
- 질의4: 취하스크립트가 채권자 유형과 리스크 수준을 반영해 과장 없이 작성되었는가?
- 질의5: 다음 담당자가 같은 결론에 재도달할 수 있도록 evidence/메모가 충분한가?
- 승인 게이트: 5문항 중 4개 미만 충족이면 HOLD, 2개 이하 충족이면 DROP으로 재분류한다.

## p04. 감정가 하한 필터
