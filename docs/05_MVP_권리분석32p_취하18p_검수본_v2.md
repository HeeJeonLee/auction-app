# MVP 매뉴얼 50P 검수본 v2

범위: 서울/수도권 아파트, 감정가 5억~50억(초과건 별도 트랙)
목표: OCR 결과를 규칙 엔진에 직접 연결해 점수/판정/취하 스크립트를 생성하고, 검수자가 즉시 반려/보완 결정을 내릴 수 있는 실무 문서를 제공한다.
버전: MVP-2026.08-v2

---

## p01. 사건 식별 필수키 정의
- 문서 단계: 권리분석
- 규칙ID: RA-01/RA-02/RA-03
- 핵심목표: 샘플 사건 1건을 기준으로 사건 식별키가 실제로 끊기지 않는지 검증한다.

### 필수 입력
- 사건번호, 법원명, 주소, 물건번호, 아파트명, 감정가, 최저매각가격, 부채총액, KB시세

### 검증 절차(SOP)
- 샘플 기준 사건: 2024타경1001 / 서울중앙지방법원 / 서울시 예시구 예시동 / 예시아파트
- 감정가 10억, 최저매각가격 8억, 낙찰예상가 9억, 부채총액 6억, KB시세 12억으로 수치 일관성을 먼저 확인한다.
- 사건번호 정규화 -> 법원명 표준화 -> 주소 동/호 분리 -> 물건번호 결합키 생성
- 원문 캡처, OCR 추출값, 규칙 evidence를 같은 사건 키로 대조한다.

### 반려/보류 기준
- 사건번호, 법원명, 주소 중 1개라도 공란이면 HOLD
- 감정가/최저가/부채총액 중 1개라도 단위 불명확이면 HOLD
- 서울/수도권 또는 5억~50억 범위를 벗어나면 DROP
- 보완 요청 시 재수집 필드와 마감시각을 같이 남긴다.

### 승인 기준
- 샘플 기준 사건에서 사건키가 1건으로만 귀속되고, 주소/물건번호가 분리 저장되면 승인한다.
- rule_version, 규칙근거, 담당자메모, 원문 캡처 링크가 함께 저장되면 승인한다.

### 샘플 판정 예시
- GO: 2024타경1001 / 서울중앙지방법원 / 예시아파트 / 감정가 10억 / 부채총액 6억
- HOLD: 사건번호는 있으나 주소가 잘려서 동/호가 불명확한 경우
- DROP: 감정가가 50억 초과이거나 법원명과 주소 권역이 불일치하는 경우

### 플랫폼 매핑
- UI는 p01 카드에 사건번호, 법원명, 주소, 감정가, 최저매각가격, 부채총액, KB시세를 같은 행으로 보여줘야 한다.
- OCR 결과가 원문과 다를 경우 카드 아래에 원문/추출본/판정을 함께 노출해야 한다.

### 검수 로그 템플릿
- [p01] [GO/HOLD/DROP] [사건번호/주소/금액 검증 결과] [보완요청 1줄] [검수자/시각]

## p33. 취하 프로세스 시작조건
- 문서 단계: 취하유도
- 규칙ID: WP-01
- 핵심목표: 무리한 접촉을 막고, 접촉 가능한 사건만 선별한다.

### 시작 전 3단계 게이트
1. 데이터 게이트: 주요채권자, 부채총액, 낙찰예상가 3필드가 모두 확인되어야 한다.
2. 정책 게이트: 서울/수도권, 아파트, 감정가 5억~50억 범위를 유지해야 한다.
3. 근거 게이트: evidence 라인 3개 이상이 PASS/FAIL 사유를 설명해야 한다.

### 실무 판단표
- GO: 3개 게이트 모두 충족, 채권자 연락경로 확보.
- HOLD: 1개 게이트 미충족, 보완 요청서 발행.
- DROP: 2개 이상 미충족 또는 정책 위반.

### 보완 요청서 템플릿
- 요청항목: 채권자명 정합화, 예상가 재산출, 배당표 근거 캡처.
- 마감시간: 영업일 기준 24시간.
- 미응답 처리: HOLD 유지 후 주간 큐에서 자동 제외.

## p35. 회수 비교 프레임 생성
- 문서 단계: 취하유도
- 규칙ID: WP-05
- 핵심목표: 경매 지속 대비 취하 합의안의 회수 효율을 수치로 비교한다.

### 비교식(운영 표준)
- 경매안 회수율 = (예상배당액 / 채권잔액) * 100
- 합의안 회수율 = (제안회수액 / 채권잔액) * 100
- 회수시점 가중치 = 경매안 개월수 - 합의안 개월수

### 필수 표 항목
- 채권잔액, 예상배당액, 제안회수액, 회수시점(개월), 집행비용, 순회수액.
- 표 미완성 시 자동 HOLD.

### 판정 기준
- 합의안 순회수액이 경매안 대비 +3% 이상이면 우선 제안.
- 금액 이익이 작더라도 회수시점이 2개월 이상 단축되면 조건부 제안.

- 핵심목표: 누가, 언제, 무엇을 근거로 결정했는지 재현 가능하게 남긴다.

### 필수 로그 스키마
- case_id: 사건번호.
- contact_at: 접촉 일시(로컬시간).
- channel: call/email/meeting.
- counterparty: 상대 담당자/부서.
- claim_summary: 핵심 주장 3줄 이내.
- evidence_refs: 캡처/문서 파일명 목록.
- next_action: 다음 행동과 마감시각.

### 필수 증빙 세트
- 통화: 통화요약 메모 + 확인 문자/메일.
- 메일: 발신 원문 + 첨부 목록 + 수신확인.
- 미팅: 참석자, 합의/보류 항목, 후속 일정.

### 반려 기준
- 채널별 필수 증빙 1개라도 누락.
- next_action 미기록.
- claim_summary가 모호어 중심으로만 작성됨.

### 보관 정책
- 최소 보관 24개월.
- 수정 이력은 덮어쓰기 금지, append only.
- 개인정보 마스킹 규칙 준수.

### 감사 추적
- 재검수 시 이전 버전 로그와 diff를 자동 비교.
- 판정 변경 시 변경자, 변경시간, 변경사유를 필수 입력.

## p48. 최종 취하 스크립트 조합
- 문서 단계: 취하유도
- 규칙ID: WP-16
- 핵심목표: 판정, 리스크, 채권자 유형을 하나의 실행 문서로 통합한다.

### 조합 순서
1. 판정요약: GO/HOLD/DROP 사유 1문장.
2. 수치근거: 회수율/회수시점 2개.
3. 리스크: 핵심 2개와 완화수단.
4. 실행계획: 금액/기한/증빙.

### 길이 규정
- 본문 8~12문장.
- 문장당 60자 내외.
- 법률 확정 표현 금지.

### 검수 기준
- 수치가 없는 문장 비중 50% 초과 시 반려.
- 실행계획 누락 시 HOLD.

## p50. 릴리스 게이트
- 문서 단계: 취하유도
- 규칙ID: WP-18
- 핵심목표: 배포 전에 데이터, 규칙, 문서 품질을 한 번에 검수한다.

### 배포 전 체크리스트
- 필수필드 채움률 90% 이상.
- 규칙판정 생성률 100%.
- 취하스크립트 생성률 95% 이상.
- 오류 로그 치명도 High 0건.
- 수동검수 샘플 10건 PASS.

### 실패 시 조치
- High 오류 1건이라도 있으면 배포 중단.
- 생성률 미달 시 원인 필드 역추적 후 재실행.
- 샘플 PASS 미달 시 규칙/문구 동시 보정.

### 배포 승인 기록
- 승인자, 승인시간, 릴리스 노트, 롤백 기준을 남긴다.
