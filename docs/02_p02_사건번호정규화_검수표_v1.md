# p02 사건번호 정규화 검수표 v1

대상 사건: 2024타경1001
정규화 기준: 2024타경1001
허용 변형: 공백, 괄호, 하이픈, OCR 오인식 일부를 보정하되 최종 저장은 하나의 표준 사건번호로 통일

## 1. 이 페이지에서 보는 것
- 사건번호가 원문과 OCR에서 같은 값으로 읽혔는지 확인한다.
- 숫자나 한글이 섞여도 최종 저장값은 표준 형식으로 하나만 남겨야 한다.
- 여기서 실패하면 같은 사건이 중복 저장된다.

## 2. 입력 필드
- 사건번호 원문
- OCR 사건번호
- 사건번호 보조표기(있을 경우)
- 원문 캡처 위치

## 3. 표준화 규칙
1. 공백 제거
2. 괄호/하이픈 제거
3. OCR 혼동 문자 보정
4. 최종 형식을 YYYY타경NNNN으로 통일
5. 보조 사건번호는 별도 메모로만 저장

## 4. 통과 기준
- 원문 사건번호와 OCR 사건번호가 동일 사건으로 귀속된다.
- 표준 사건번호가 1개만 저장된다.
- 보조표기는 메모에만 남고 본문 사건번호를 오염시키지 않는다.

## 5. 보류 기준
- 사건번호가 '타경'으로 끝까지 읽히지 않으면 HOLD.
- 숫자 4자리가 다 읽히지 않으면 HOLD.
- 사건번호와 물건번호가 섞여 보이면 HOLD.
- 원문 캡처가 없으면 HOLD.

## 6. 반려 기준
- 사건번호가 아예 판독되지 않으면 DROP.
- 표준화 후에도 사건번호가 두 개 이상 남으면 DROP.
- 다른 사건번호와 병합되면 DROP.

## 7. 샘플 판정 예시
- GO: 2024타경1001 / 2024타경1001(원문 변형 포함)
- HOLD: 2024타경10O1처럼 숫자/문자 혼동이 남아 있는 경우
- DROP: 사건번호가 비어 있거나 완전히 다른 사건번호로 읽힌 경우

## 8. 기록할 것
- [p02] [GO/HOLD/DROP]
- 원문 사건번호
- OCR 사건번호
- 표준화 결과
- 보정 이유
- 검수자/시각

## 9. 플랫폼에서 확인할 것
- UI는 p02 카드에 원문 사건번호와 OCR 사건번호를 나란히 보여줘야 한다.
- 표준화 후 저장값은 한 줄로만 남아야 한다.
- 보조표기는 본문 사건번호와 분리해서 보여줘야 한다.

## 10. 다음 작업 기준
