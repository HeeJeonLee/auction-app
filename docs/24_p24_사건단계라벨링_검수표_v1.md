# p24 사건 단계 라벨링 검수표 v1

대상 사건: 2024타경1001
법원: 서울중앙지방법원
주소: 서울시 예시구 예시동
아파트: 예시아파트
유찰횟수: 2회
낙찰예상가: 900,000,000원
단계 라벨: 재검토

## 1. 이 페이지에서 보는 것
- 유찰이 몇 번 있었는지 보고 단계가 바뀌는지 확인한다.
- 유찰이 많은데도 아무 보정 없이 같은 단계로 두지 않는지 본다.
- 라벨이 숫자와 메모를 같이 따라가는지 확인한다.

## 2. 입력 필드
- 유찰횟수
- 낙찰예상가
- 단계 라벨
- 보정 전 값
- 보정 후 값

## 3. 판정 순서
1. 유찰 횟수를 먼저 본다.
2. 낙찰예상가가 어떻게 달라졌는지 확인한다.
3. 보정 전후 값이 왜 바뀌었는지 메모를 본다.
4. 단계 라벨이 그 변화와 맞는지 확인한다.

## 4. 통과 기준
- 유찰 횟수에 맞는 단계 라벨이 붙는다.
- 보정 전후 값이 같이 남아 있다.
- 라벨이 숫자와 메모를 동시에 설명한다.

## 5. 보류 기준
- 유찰은 많지만 라벨이 그대로면 HOLD.
- 보정 전후 차이가 있는데 이유가 없으면 HOLD.
- 숫자만 있고 단계 설명이 없으면 HOLD.

## 6. 반려 기준
- 유찰 다수인데 보정 없이 그대로 두면 DROP.
- 다른 사건 유찰 횟수를 가져오면 DROP.
- 단계 라벨과 숫자가 끝내 안 맞으면 DROP.

## 7. 샘플 판정 예시
- GO: 유찰 2회 / 보정 후 재검토 / 메모에 근거 있음
- HOLD: 유찰 횟수는 있으나 보정 이유가 비어 있는 경우
- DROP: 유찰이 많은데도 일반 단계로 남긴 경우

## 8. 기록할 것
- [p24] [GO/HOLD/DROP]
- 유찰횟수
- 보정 전 값
- 보정 후 값
- 단계 라벨
- 검수자/시각

## 9. 플랫폼에서 확인할 것
- UI는 유찰 횟수와 단계 라벨을 같이 보여줘야 한다.
- 보정 전후 값이 없으면 완료 카드로 보여주면 안 된다.
- 유찰이 많은데 일반 단계가 뜨면 안 된다.
