# p13 권리요약 생성 품질 검증 검수표 v1

대상 사건: 2024타경1001
법원: 서울중앙지방법원
주소: 서울시 예시구 예시동
아파트: 예시아파트
권리요약: 근저당 1, 압류 1, 부채총액 확인 필요
권리플래그: 근저당/압류

## 1. 이 페이지에서 보는 것
- 권리요약이 공란이 아닌지 확인한다.
- 핵심 리스크가 최소 2개 이상 들어 있는지 본다.
- 반복문처럼 비어 있는 요약이 아닌지 확인한다.

## 2. 입력 필드
- 권리요약
- 권리플래그
- 사건번호
- 법원명
- 주소

## 3. 판정 순서
1. 권리요약 문장을 먼저 읽는다.
2. 핵심 리스크가 최소 2개 들어 있는지 센다.
3. 권리플래그와 요약 내용이 일치하는지 본다.
4. 공란이나 반복문인지 확인한다.

## 4. 통과 기준
- 권리요약이 공란이 아니다.
- 핵심 리스크 2개 이상이 들어 있다.
- 권리플래그와 요약이 같은 사건을 가리킨다.

## 5. 보류 기준
- 요약은 있으나 너무 짧아 핵심이 빠지면 HOLD.
- 권리플래그는 있으나 요약이 비면 HOLD.
- 사건별 표현이 섞여 있으면 HOLD.

## 6. 반려 기준
- 권리요약이 공란이면 DROP.
- 핵심 리스크 2개 미만이면 DROP.
- 다른 사건 요약을 끌어오면 DROP.

## 7. 샘플 판정 예시
- GO: 근저당 1, 압류 1, 부채총액 확인 필요
- HOLD: 권리플래그는 있으나 요약이 한 줄 메모 수준인 경우
- DROP: 권리요약이 공란이거나 다른 사건 문장을 붙인 경우

## 8. 기록할 것
- [p13] [GO/HOLD/DROP]
- 권리요약
- 핵심 리스크 수
- 권리플래그 일치 여부
- 검수자/시각

## 9. 플랫폼에서 확인할 것
- UI는 권리요약과 권리플래그를 같이 보여줘야 한다.
- 공란 요약을 승인 카드로 보여주면 안 된다.
- 핵심 리스크가 부족하면 보류로 내려야 한다.
