# p49 운영 태그/버전 기록 검수표 v1

대상 사건: 2024타경1001
제안유형: 취하 유도 최종안

## 1. 이 페이지에서 막는 것
- 버전 태그 없이 결과를 출력하는 행위
- 재분석인데 이전 실행과 비교 기록이 없는 상태
- 관리자 권한 없이 태그를 바꾸는 행위

## 2. 필수 태그
- rule_version
- manual_version
- run_timestamp
- operator_id
- dataset_hash

## 3. 운영 규칙
- 버전 태그 누락 건은 보고서 출력 금지
- 동일 사건 재분석 시 이전 태그와 비교 표시
- 태그 변경은 관리자 권한으로만 허용

## 4. 점검 항목
- 결과 파일과 대시보드 버전 불일치 여부
- 수동수정 이력 존재 여부

## 5. 통과 예시
- 5개 필수 태그가 모두 존재함
- 재분석 시 이전 태그와 diff가 자동 표시됨
- 태그 변경 기록에 변경자와 승인자가 남음

## 6. 판정 순서
1. 필수 태그 5개 존재 여부를 본다.
2. 재분석 비교 표시 여부를 본다.
3. 권한 로그를 본다.
4. 하나라도 비면 GO를 주지 않는다.

## 7. 보류 기준
- 태그는 있는데 dataset_hash가 비어 있으면 HOLD.
- 비교 표시는 있는데 변경자 기록이 없으면 HOLD.
- 수동수정 이력은 있는데 사유가 없으면 HOLD.

## 8. 반려 조건
- 필수 태그 누락 상태에서 출력 시도.
- 관리자 권한 없이 태그 변경.
- 버전 불일치인데 무시하고 배포 진행.

## 9. UI 확인
- 필수 태그가 한 화면에 보이고 누락이 즉시 표시돼야 한다.
- 재분석 비교(diff) 영역이 기본 노출돼야 한다.
- 권한 없는 태그 수정 버튼은 비활성화돼야 한다.

## 10. 다음 작업

- 태그 누락은 OCR보다 운영 통제 이슈로 먼저 분리한다.
